「アプリを使い始める人」と「ソースからビルド・開発する人」で必要な作業が異なる。次表で読み分け、詳細は各リンク先を参照する。

## 1. インストール手順（利用者向け）

**対象**: 配布された **.msix** と **.cer** を受け取り、PC にアプリを入れて使う人。

**不要なもの**: Python / Rust のインストール（配布版に `sudachi_ffi.dll` と辞書が同梱される）。

**手順の全体像**:

1. **.NET 8 デスクトップ ランタイム**が未導入ならインストール（MSIX 実行時に案内される場合あり）。
2. **証明書（.cer）** を「信頼されたルート証明機関」に追加する（初回のみ。GUI または PowerShell）。
3. **.msix** をダブルクリックしてアプリをインストールする。
4. 起動後、**設定**で検索対象フォルダを追加し、**再構築**でインデックスを作成する。

**詳細（コマンド例・トラブルシュート含む）**は **[社内配布手順.md](社内配布手順.md)** の「利用者向け：インストール手順」を参照する。

利用中の操作は **[操作マニュアル.md](操作マニュアル.md)** を参照する。

## 2. 環境構築手順（開発者向け）

**対象**: 本リポジトリを取得し、**ビルド・実行・デバッグ**する人。

### 2.1 必要な環境

| 項目 | 内容 |
|------|------|
| OS | Windows 10 / 11（64bit） |
| .NET | **.NET 8 SDK**（8.0.4xx 系推奨。[ダウンロード](https://dotnet.microsoft.com/download/dotnet/8.0)） |
| ワークロード | **.NET MAUI**（Windows 向け。`dotnet workload install maui`） |
| Sudachi 同梱物 | リポジトリにコミット済み（`tools/sudachi/`。checkout / update で取得） |
| PowerShell | 辞書 ZIP の初回展開に使用（Windows 標準で可） |
| IDE | 任意（Visual Studio 2022 / VS Code / Rider 等） |

※ 開発 PC では Sudachi の再ビルド・外部ダウンロードは行わない（同梱物をそのまま使う）。  
※ Rust は **ビルド担当者が DLL を作るときだけ** 必要。通常の開発者 PC では不要。  
※ Python は不要。  
※ 検索・プレビューで Office をインストールする必要はない（テキスト抽出のみ）。ファイルを「開く」操作で Office が使われる場合がある。

### 2.2 Sudachi 同梱物

`tools\sudachi\` はリポジトリに含める。開発者は **社内 SVN の checkout / update** で一式を得る（開発用ミラーで Git を使う場合は clone / pull でも可）。

| ファイル | 説明 |
|---------|------|
| `sudachi_ffi.dll` | win-x64 用 DLL |
| `resources/system_core.dic.zip` | 辞書 ZIP（約 73MB。ビルド時に展開） |
| `resources/sudachi.json` | 設定 |
| `resources/char.def` / `unk.def` | リソース |

初回 `dotnet build` 時に ZIP が `resources/system_core.dic`（約 207MB）へ自動展開される。展開済み `.dic` は `.gitignore` 対象でコミット不要。

**ビルド担当者**が初回または DLL 更新時にビルドし、リポジトリへコミットする。手順は [tools/sudachi/README.md](../tools/sudachi/README.md)。

### 2.3 SDK と MAUI ワークロードの導入

1. [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0) をインストールする。
2. バージョンを確認する。

```powershell
dotnet --version
```

3. MAUI ワークロードを入れる（未導入だと `FileSearch.Blazor` のビルドが失敗しやすい）。

```powershell
dotnet workload install maui
```

Visual Studio 2022 で「.NET マルチプラットフォーム アプリ UI 開発」を入れている場合は省略できることがある。ビルドエラー時は必ず実行する。

4. 導入確認。

```powershell
dotnet workload list
```

`maui` または `maui-windows` が表示されていればよい。

### 2.4 リポジトリの取得

**社内 SVN（通常）:**

```powershell
svn checkout <社内リポジトリURL> C:\全文検索システム   # 未入手の場合
cd C:\全文検索システム
svn update                                            # 同梱物を含め最新化
```

**開発用 Git ミラー（任意）:**

```powershell
git clone <リポジトリURL> C:\全文検索システム
cd C:\全文検索システム
```

**重要:** `tools/sudachi/` 一式が揃っていること。次のファイルが存在するか確認する。

```
tools/sudachi/sudachi_ffi.dll
tools/sudachi/resources/system_core.dic.zip
tools/sudachi/resources/sudachi.json
tools/sudachi/resources/char.def
tools/sudachi/resources/unk.def
```

不足時は `svn update`（または `git pull`）で最新化する。

### 2.5 ビルド

リポジトリルートで実行する。

```powershell
cd C:\全文検索システム
dotnet restore
dotnet build
```

**初回ビルドの注意:**

- `system_core.dic.zip` の展開に **1〜3 分** かかることがある。
- 成功時は `ビルドに成功しました。` と表示される。

### 2.6 実行（デバッグ）

```powershell
dotnet run --project src\FileSearch.Blazor
```

または Debug 構成の exe を直接起動する。

```
src\FileSearch.Blazor\bin\Debug\net8.0-windows10.0.19041.0\win10-x64\FileSearch.Blazor.exe
```

Debug 構成は `WindowsPackageType=None` のため exe 直起動が可能。ターゲットフレームワークは環境により `net8.0-windows10.0.x` 等が指定される。

### 2.7 よくある失敗と対処

| エラー・症状 | 原因 | 対処 |
|-------------|------|------|
| `NETSDK1147` 等 MAUI 関連 | MAUI ワークロード未導入 | `dotnet workload install maui` |
| `Sudachi 辞書がありません` | `system_core.dic.zip` 欠落 | `svn update` で `tools/sudachi/resources/` を復元 |
| `Sudachi 同梱物 (tools\sudachi\) がありません` | `sudachi_ffi.dll` 欠落 | 同上 |
| 初回ビルドで PowerShell エラー | 実行ポリシー等 | `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser`、または下記の手動展開 |
| `dotnet clean -f net8.0-...` で失敗 | MAUI プロジェクトの制約 | `dotnet clean` のみ使う（`-f` は付けない） |
| **Release** の exe を直起動してクラッシュ | Release は MSIX モード | 開発は **Debug** を使う。配布用は `scripts/build-dist.ps1` |

辞書の手動展開（自動展開が失敗した場合）:

```powershell
Expand-Archive -LiteralPath tools\sudachi\resources\system_core.dic.zip -DestinationPath tools\sudachi\resources -Force
```

### 2.8 Release ビルドと配布（参考）

```powershell
dotnet build -c Release
```

Release は MSIX パッケージ生成モードになる。`bin\Release\...\FileSearch.Blazor.exe` の直起動はクラッシュしやすい（仕様）。

社内配布 ZIP が必要な場合:

```powershell
pwsh -File scripts\build-dist.ps1
```

MSIX の再作成・証明書・配布物のまとめ方は **[社内配布手順.md](社内配布手順.md)** の「配布者向け」を参照する。

### 2.9 最短チェックリスト

1. Windows 10/11 64bit
2. .NET 8 SDK インストール済み
3. `dotnet workload install maui` 実行済み
4. SVN で `tools/sudachi/` 一式取得済み（`svn update`）
5. リポジトリルートで `dotnet restore` → `dotnet build`
6. `dotnet run --project src\FileSearch.Blazor` で起動確認

### 2.10 注意

- **アナライザ（Sudachi）や Lucene のフィールド定義を変えた**場合、既存インデックスと互換がなくなることがある。そのときはアプリ内で **全体を再構築**する。
- リポジトリ直下の [README.md](../README.md) にも概要・プロジェクト構成がある。

## 3. 用語の対応

| 用語 | 意味 |
|------|------|
| **インストール** | 利用者が **MSIX（または配布物）を PC に入れてアプリを使える状態にする**こと。 |
| **環境構築** | 開発者が **SDK・言語ランタイム・依存関係をそろえ、ソースからビルド・実行できる状態にする**こと。 |

両方とも「セットアップ」と呼ばれることがあるが、本ドキュメントでは上記のように区別する。
