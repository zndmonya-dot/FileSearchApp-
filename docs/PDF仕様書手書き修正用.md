# PDF 仕様書 手書き修正用資料

**目的**: 紙／PDF 形式の旧仕様書（例: `01要件定義書.pdf`、`02外部設計書.pdf` 等）を、手書きまたは PDF 注釈で現行実装に合わせて直すための差分一覧です。

**基準日**: 2026-06-21  
**正（ソース・オブ・トゥルース）**: リポジトリ内 Markdown（[要件定義.md](要件定義.md)、[外部設計.md](外部設計.md) 等）および `src/` のコード

---

## 使い方

1. 手元の PDF を開き、下表の **「PDF で探すキーワード」** で該当箇所を探す。
2. **「旧記述（PDF にありがち）」** を見つけたら、**「現行（書き換え後）」** に差し替える（または追記・削除）。
3. **「PDF 頁」** 列に、実際のページ番号をメモしてチェック（□ → ☑）。
4. 新規追加項目（REQ-5.8 等）は、該当章の末尾に **追記** する。
5. 完了後、本ファイルの「修正完了チェックリスト」に ☑ を入れる。

## 1. 要件定義書 PDF 向け

### 1.1 機能要件（REQ 番号付き）

| □ | PDF 頁 | REQ / 章 | PDF で探すキーワード | 旧記述（PDF にありがち） | 現行（書き換え後） |
|---|--------|----------|----------------------|--------------------------|-------------------|
| □ | | REQ-2.3 | 進捗表示、スキップ | 構築中にスキップ件数を表示する | **構築中**は処理済み数／総数／現在ファイル（tooltip）／**残り時間 ETA（推定可能時）**。**構築中はスキップ件数を表示しない**。完了後にスキップがあればフッターに件数＋ログを開ける |
| □ | | REQ-5.6 | Esc、検索クリア | Esc で検索クエリとエラー表示をクリア | Esc で **閲覧モードへ復帰**（クエリ・検索結果・選択をクリアしフォルダツリーを再表示）。空クエリで検索ボタン押下も同様 |
| □ | | REQ-6.4 | appmode、60秒、同期 | 60 秒ごとに再読み込み | **起動時に読み込み**。共有設定の反映は **アプリ再起動**（60 秒ポーリングは行わない） |
| □ | | §3.6 | 対応拡張子、Office | .docx, .xlsx, .pptx のみ／.js 等を列挙 | **31 種**（下記「拡張子一覧」参照）。**.doc / .xls は NPOI**。.js / .htm / .yaml 等は **非対応** |
| □ | | §4.2 | 並列度、Sudachi | パイプライン ≈ 4、Sudachi プール最大 2 | Sudachi プール `max(2, min(8, ProcessorCount/2))`。IndexWriter RAM 256MB、マージスレッド 1 |
| □ | | **新規** | — | （記載なし） | **REQ-5.8** を追記: サイドバー見出しは常に **「全文検索システム」**（検索中・閲覧中で切り替えない） |
| □ | | REQ-3.1a | 検索モード | （旧 PDF に無い場合） | **AND検索 / OR検索 / 完全一致検索** の 3 モード（6/07 追加） |
| □ | | REQ-1.5 | 自動更新 | 30分・1時間間隔 | **JST 0〜23 時グリッド**（複数選択可）。未選択で無効 |
| □ | | REQ-2.5 | 1MB | 文字数上限等 | **1MB 超でスキップ**（`ContentLimits.IndexMaxFileBytesForExtract`）。1MB 以下は文字数打ち切りなし |

### 1.2 拡張子一覧（§3.6 を丸ごと差し替え用）

PDF の表を以下に置き換える（**計 31 種**）。

| 種別 | 拡張子 | 備考 |
|------|--------|------|
| Office | .doc, .docx, .xls, .xlsx, .xlsm, .pptx | .docx/.xlsx/.pptx = Open XML SDK、**.doc/.xls = NPOI** |
| Outlook | .msg | MsgReader |
| PDF | .pdf | PdfPig |
| テキスト・スクリプト | .txt, .md, .log, .csv, .bat, .ps1, .sh | TextFileExtractor |
| ソース・設定 | .html, .xml, .cs, .java, .ts, .dfm, .pas, .dpr, .dpk, .ini, .env, .json, .py, .css, .sql | TextFileExtractor |

※ 非対応の例: `.js`, `.htm`, `.yaml`, `.yml`, `.jsx`, `.tsx`, `.cpp`, `.c`, `.h`

## 2. 外部設計書 PDF 向け

### 2.1 メイン画面（SCR-1）

| □ | PDF 頁 | 項目 | PDF で探すキーワード | 旧記述 | 現行 |
|---|--------|------|----------------------|--------|------|
| □ | | 起動 | スプラッシュ、3秒 | 最低 3 秒表示 | 最低 **約 2.6 秒**（`boot-splash.js`）。段階メッセージ＋進捗バー |
| □ | | 版表示 | v2.0、BootSplashVersion | 固定文言 v2.0 | **`AppVersion.Label`**（csproj の `ApplicationDisplayVersion` → WebView 注入） |
| □ | | サイドバー見出し | 検索結果、フォルダ | モードで「検索結果」／「フォルダ」切替 | 常に **「全文検索システム」** |
| □ | | ウィンドウタイトル | Panoleon | Panoleon v2.0 固定等 | **`Panoleon v{版}`**（`AppWindowTitle.Current`） |
| □ | | 検索進捗 | n/N 件、FormatSearchProgress | ツリー内 `（n/N 件）` | **CuteLoader（スピナーのみ）**。件数進捗・件数バッジ **なし** |
| □ | | ツリー空 | Enter で検索 | Enter で検索 | **検索ボタンまたは Enter で検索** |
| □ | | インデックス進捗 | スキップ N 件（構築中） | 進捗行にスキップ件数 | 構築中: **％ + ETA** + 処理数/総数。**スキップ件数は構築中非表示** |
| □ | | Esc | クリア | クエリクリアのみ | **閲覧モード復帰**（ツリー再構築・選択クリア） |
| □ | | 閲覧 | 検索前 | （検索後のみツリー） | **起動時から**フォルダツリー閲覧可 |
| □ | | 一覧列 | 名前・日付 | 2 列 | **名前 / 内容 / 更新日時**（内容列は 6/14 追加） |

### 2.2 設定モーダル（SCR-2）

| □ | | 保存ボタン | 緑、GitHub 風 | **青系プライマリ**（`settings-btn-primary`） |

## 7. 手書き用：そのまま転記できる短文

PDF の余白や付箋に書き写すとき用（短い版）。

```
【サイドバー】見出しは常に「全文検索システム」
【Esc】閲覧モードへ復帰（検索前のフォルダツリー）
【検索中】スピナーのみ（件数 n/N 表示なし）
【構築中】％＋ETA＋処理数/総数（スキップ件数は出さない）
【構築完了後】スキップがあればフッターに件数
【起動】スプラッシュ最低2.6秒、版はAppVersion注入
【更新DLG】2カード選択、進捗はフッター、実行ボタン青
【保存】設定保存ボタン青
【appmode】起動時読込、変更は再起動（60秒同期なし）
【拡張子】31種（.doc/.xls=NPOI、.ts/.json追加、.js非対応）
```
