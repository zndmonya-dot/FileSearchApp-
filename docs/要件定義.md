# 要件定義書

## 1. はじめに

### 1.1 目的

本ドキュメントは、Panoleon（社内ファイルサーバ向け全文検索システム、以下「本システム」）の要件を定義する。

### 1.2 スコープ

- 対象: 社内のファイルサーバ（UNC パス）上に格納された文書・ファイルの全文検索
- 対象外: メール、クラウドストレージ、Web 上のコンテンツなどは本システムのスコープ外とする

---

## 2. システム概要

### 2.1 背景・目的

社内のファイルサーバには大量の文書（Word、Excel、PDF、テキストなど）が格納されている。利用者がキーワードで検索し、目的のファイルを素早く見つけられるようにすることを目的とする。

### 2.2 システムの位置づけ

- Windows 向けのデスクトップアプリケーション（Blazor Hybrid / MAUI）
- 利用者は社内の PC に本アプリをインストールし、自ら設定した「検索対象フォルダ」に対して全文検索を行う
- 検索エンジンとして Lucene.NET を、日本語形態素解析に Sudachi を使用する

---

## 3. 機能要件

### 3.1 設定機能

| No. | 機能 | 説明 |
|-----|------|------|
| REQ-1.1 | 検索対象フォルダの設定 | 検索対象とするフォルダ（UNC パス含む）を複数登録・保存できること。手入力のほか、OS のフォルダ選択ダイアログ（参照ボタン）でも追加できること |
| REQ-1.2 | 対象拡張子の設定 | インデックス対象とするファイル拡張子を指定できること（未指定時は対応する全拡張子を使用） |
| REQ-1.3 | インデックス保存先の設定 | インデックスを保存するローカルフォルダを指定できること |
| REQ-1.4 | プレビュー切り替え遅延 | ファイル選択からプレビュー読み込みまでの待ち時間は **コード上 200ms（デバウンス）で固定** である（`Home.razor.cs` の `PreviewDebounceMs` を `Home.Preview.cs` が使用）。`AppSettings` および設定画面には項目を持たない |
| REQ-1.5 | 自動更新（差分更新）の設定 | 毎日指定した時刻（日本時間・0〜23時、複数選択可）に差分更新するかどうかを設定できること。未選択（無効）のときは自動更新しない |
| REQ-1.6 | テーマの設定 | 表示テーマ（ダークモード / ライトモード / システムに従う）を選択できること |

### 3.2 インデックス機能

| No. | 機能 | 説明 |
|-----|------|------|
| REQ-2.1 | インデックス再構築 | 指定フォルダ群についてインデックスを全削除のうえ全件再作成できること |
| REQ-2.2 | インデックス差分更新 | 追加・更新・削除されたファイルのみを反映する差分更新ができること（大量ファイルで高速） |
| REQ-2.3 | 進捗表示 | インデックス作成・更新時に **構築中**は処理済み数／総数／現在ファイル（tooltip）／残り時間（ETA、推定可能時のみ）を表示すること。**構築中はスキップ件数を表示しない**。完了後、スキップがあればフッターに件数を表示し、ログを開けること |
| REQ-2.4 | 自動更新 | 設定した時刻（JST）でインデックスを**差分更新**できること（オプション）。管理者 PC のみ実行し、利用者の検索中は見送る |
| REQ-2.5 | 大容量ファイルのスキップ | **1MB**（`ContentLimits.IndexMaxFileBytesForExtract`）を超えるファイルや抽出エラーが発生したファイルはスキップし、次のファイルへ処理を継続すること（本文をインデックスに含めない。境界は「超過」のみ） |
| REQ-2.6 | スキップログの出力 | スキップされたファイルのパスと理由をログファイル（`skipped_files.log`）に出力し、UI にスキップ件数を表示すること |

### 3.3 検索機能

| No. | 機能 | 説明 |
|-----|------|------|
| REQ-3.1 | キーワード全文検索 | インデックス済みテキストに対してキーワードで全文検索できること |
| REQ-3.1a | 検索モード | **AND検索**（各語をすべて部分一致）、**OR検索**（いずれか部分一致）、**完全一致検索**（入力文字列の連続一致）を切り替えられること |
| REQ-3.2 | 日本語形態素解析 | 日本語を形態素単位で分割し、適切に検索できること（Sudachi モード C） |
| REQ-3.3 | 検索結果一覧表示 | ヒットしたファイルをフォルダ階層ツリーで表示し、ファイル名・更新日時等を表示すること |
| REQ-3.4 | マッチ箇所の表示 | 検索キーワードがヒットした箇所をプレビューおよびフォルダ一覧の「内容」列で抜粋し、ハイライト表示すること |
| REQ-3.5 | 検索オプション | 検索件数上限なし（内部実用上限のみ）。ファイル種類・日付・フォルダフィルターは UI 未対応 |

### 3.4 プレビュー機能

| No. | 機能 | 説明 |
|-----|------|------|
| REQ-4.1 | テキストプレビュー | テキスト・ソースコードファイルをその内容でプレビュー表示すること |
| REQ-4.2 | Office/PDF プレビュー | Word / Excel / PowerPoint / PDF をテキスト抽出した行表示でプレビューすること（表形式・ネイティブプレビューは行わない） |
| REQ-4.3 | （REQ-4.2 に統合） | — |
| REQ-4.4 | プレビュー内ハイライト | 検索クエリに合わせてプレビュー内のマッチ箇所をハイライトすること |
| REQ-4.5 | プレビュー切り替え | 検索結果でファイル選択を変更した際、**200ms** デバウンス後にプレビュー取得を行うこと。待ち時間の定数 `PreviewDebounceMs` は `Home.razor.cs`、デバウンス後の取得処理は `Home.Preview.cs` の `SchedulePreviewLoad` / `LoadPreview`（連続クリック時の無駄な抽出を抑える） |

### 3.5 操作・キーボード

| No. | 機能 | 説明 |
|-----|------|------|
| REQ-5.1 | 検索結果の選択 | 検索結果ツリー・フォルダ一覧の選択は **マウスクリック** で行う。上下キーでの選択移動は未実装 |
| REQ-5.2 | ファイルを開く | プレビュー表示中の **「開く」ボタン** で、選択中のファイルを関連アプリで開くこと。**Enter キーでは開かない**（検索欄の Enter は検索実行のみ） |
| REQ-5.3 | フォルダを開く | プレビュー表示中の **「フォルダ」ボタン** で、選択中のファイルの親フォルダをエクスプローラーで開くこと。**Ctrl+Enter は未実装** |
| REQ-5.4 | パスコピー | **未実装**（クリップボードへのコピー操作は現行 UI にない） |
| REQ-5.5 | 検索フォーカス | **未実装**（グローバル Ctrl+F で検索欄へフォーカスする処理はない。初期表示時はルーティングで検索入力にフォーカスを移す） |
| REQ-5.6 | Esc で閲覧モード復帰 | 検索入力欄にフォーカスがある状態で **Esc** を押すと、検索クエリをクリアし **閲覧モード**（検索前のフォルダツリー）へ戻ること。空の検索語で検索ボタンを押した場合も同様 |
| REQ-5.7 | 領域別ズーム | **Ctrl + マウスホイール** で、左サイドバー（検索結果ツリー側）と右メイン領域（プレビュー／フォルダ一覧側）を **独立に拡大／縮小** できること（倍率は 0.5〜3.0、10% 刻み）。**Ctrl + 0** でカーソル／フォーカスのある側のみ等倍に戻せること。WebView の既定の全体ズームは抑止する。倍率は永続化せず、**アプリ再起動・再描画で等倍に戻る** |
| REQ-5.8 | サイドバー見出し | サイドバー上部の見出しは常に **「全文検索システム」** と表示すること（検索中・閲覧中で切り替えない） |

### 3.6 対応ファイル形式

| 種別 | 拡張子 | 備考 |
|------|--------|------|
| Office | .doc, .docx, .xls, .xlsx, .xlsm, .pptx | .docx / .xlsx / .pptx は Open XML SDK、**.doc / .xls は NPOI** |
| Outlook | .msg | MsgReader |
| PDF | .pdf | PdfPig |
| テキスト・スクリプト | .txt, .md, .log, .csv, .bat, .ps1, .sh | TextFileExtractor |
| ソース・設定 | .html, .xml, .cs, .java, .ts, .dfm, .pas, .dpr, .dpk, .ini, .env, .json, .py, .css, .sql | TextFileExtractor（**計 31 種**。正は `SupportedExtensionSets`） |

※ `.js` / `.htm` / `.yaml` 等は現行版では非対応。

### 3.7 共有インデックス・動作モード

| No. | 機能 | 説明 |
|-----|------|------|
| REQ-6.1 | 共有インデックス参照 | `appmode.json` で共有インデックスパスを指定し、複数 PC から同一インデックスを参照できること |
| REQ-6.2 | 管理者 / 非管理者 | ローカルアカウントは管理者、AD ドメインアカウントは参照専用（再構築・自動更新・共有設定変更不可） |
| REQ-6.3 | shared.json | 管理者が設定保存時にインデックスフォルダへ `shared.json` を自動出力し、利用者 PC が起動時に読み込むこと |
| REQ-6.4 | appmode 同期 | `appmode.json` / `shared.json` は **起動時に読み込み**。管理者が保存した共有設定の反映は **アプリ再起動**（60 秒ポーリングは行わない） |

## 4. 非機能要件

### 4.1 動作環境

| 項目 | 要件 |
|------|------|
| OS | Windows 10 / 11 専用 |
| ランタイム | .NET 8 SDK |
| 形態素解析 | **Sudachi ネイティブ**（`sudachi_ffi.dll` / sudachi.rs モード C）。辞書・DLL は配布物に同梱。開発時は Rust で初回ビルド |
| プレビュー | 不要（全形式ともテキスト抽出で表示。Office はファイルを開く際に利用可能） |

### 4.2 パフォーマンスと上限（必要最低限）

| 項目 | 値 | 適用範囲 |
|------|-----|----------|
| ファイルサイズ | **1MB 超でスキップ** | インデックス本文抽出・テキスト読込・プレビュー試行（REQ-2.5） |
| 本文（1MB 以下） | **文字数打ち切りなし** | 抽出全文を Sudachi・Lucene 保存・バイグラム・プレビューに使用 |
| Lucene 1 トークン | **32,765 バイト（UTF-8）** | 技術的上限（超過語は分割） |

その他:

- 初回検索の遅延を軽減するため、インデックス読み込み・アナライザのウォームアップ（Sudachi 辞書の事前ロード）を行う
- 大量ファイルがある場合、再構築ではなく差分更新により短時間でインデックスを更新できるようにする
- 形態素解析はプロセス内のネイティブ DLL で行う。インデックス構築の並列度は `SudachiTokenizer.PoolSize`（`max(2, min(8, ProcessorCount/2))`）に合わせ、IndexWriter RAM 256MB、マージスレッド 1

### 4.3 互換性・運用

- 形態素解析（アナライザ）を変更した場合、既存のインデックスは互換性がなくなる。その場合は「インデックスを再構築」を実行すること

### 4.4 セキュリティ・配布

- 社内配布時は MSIX パッケージと証明書をセットで配布する手順に従う（別途「社内配布手順」参照）
- 証明書不要のスタンドアロン exe（ZIP）配布もビルドスクリプトで生成可能とする

---

## 5. 制約・前提

- 本システムは Windows 専用であり、他 OS は対象としない
- 検索対象は「利用者が設定したフォルダ」に限定され、端末内の全ドライブを自動で対象にはしない
- ファイルサーバへのアクセスは、実行環境のネットワーク・権限に依存する

## 6. 用語・略語

| 用語 | 説明 |
|------|------|
| インデックス | 検索用にファイルから抽出したテキストを格納したデータ。Lucene により管理される |
| 形態素解析 | 文を意味の最小単位（形態素）に分割すること。日本語検索の精度向上に利用する |
| Sudachi | 日本語形態素解析器。本システムでは sudachi.rs ベースのネイティブ DLL（モード C）を使用する |
| Lucene | Apache Lucene。全文検索エンジン。本システムでは Lucene.NET を使用する |
| UNC パス | 例: `\\server\share\folder` のようなネットワークパス |
