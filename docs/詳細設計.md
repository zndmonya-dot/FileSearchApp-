# 詳細設計書

## 1. はじめに

本ドキュメントは、社内ファイルサーバ向け全文検索システムの内部設計（モジュール構成・インターフェース・クラス・データ構造）を定義する。外部仕様は「外部設計書」を参照すること。

---

## 2. アーキテクチャ概要

### 2.1 レイヤー構成

```mermaid
flowchart TB
  subgraph Blazor [FileSearch.Blazor]
    UI[Components/Pages/Shared]
    UISvc[Services]
  end
  subgraph Messages [FileSearch.Messages]
    UM[UserMessages]
  end
  subgraph Core [FullTextSearch.Core]
    Index[Index]
    Search[Search]
    Preview[Preview]
    Extractors[Extractors]
    Models[Models]
    IdxMsg[IndexMessages]
  end
  subgraph Infra [FullTextSearch.Infrastructure]
    Lucene[Lucene]
    ExtImpl[Extractors]
    Sudachi[Sudachi]
    Settings[Settings]
  end
  Blazor --> Core
  Blazor --> Infra
  Blazor --> Messages
  Infra --> Core
```

- **FileSearch.Blazor**: UI 層。Blazor Hybrid (MAUI)。Core のインターフェースと Infrastructure の実装を DI で利用する。画面文言は **FileSearch.Messages** を参照する。
- **FileSearch.Messages**: 画面向けユーザー文言のみを集約した小さなプロジェクト（`UserMessages`）。Core の `IndexMessages`（インデックス・ログ）と役割を分ける。
- **FullTextSearch.Core**: インターフェース・モデル・共有ロジック。インフラに依存しない。
- **FullTextSearch.Infrastructure**: 検索・インデックス・抽出・設定の実装。Core を参照する。

### 2.2 依存関係

- Blazor → Core（ISearchService, IIndexService, IPreviewService, ITextExtractor, Models）
- Blazor → Infrastructure（IAppSettingsService および各実装クラス。MauiProgram で DI 登録）
- Blazor → FileSearch.Messages（`UserMessages`。プロジェクト参照）
- Infrastructure → Core（インターフェース・モデル・DefaultPaths 等）
- Tests → Core / Infrastructure / FileSearch.Messages（単体テスト）

### 3.3 FileSearch.Blazor

| フォルダ | 役割 | 主なファイル |
|----------|------|--------------|
| Components/Pages | メイン画面（1 ページを partial で分割） | `Home.razor`（マークアップ）、`Home.razor.cs`（状態・ライフサイクル・Dispose・テーマ・`PreviewDebounceMs` 等の定数）、`Home.Search.Tree.cs`（検索・ツリー・フォルダ表・キーボード）、`Home.Preview.cs`（プレビュー・ハイライトナビ・ファイル/フォルダを開く）、`Home.Index.cs`（インデックス再構築・差分・進捗・スキップログ）、`Home.Settings.cs`（設定モーダル）、`Home.Resize.cs`（サイドバー幅ドラッグ・プレビュー行表示用キャッシュ） |
| Components/Shared | 共通コンポーネント | SearchSidebar, SearchResultTree, FilePreviewView, FolderListView, SettingsModal, IndexUpdateDialog, AppHeader 等 |
| Components/Layout | レイアウト | MainLayout.razor |
| Services | UI 用サービス | PreviewService, TreeBuilder |
| Platforms/Windows | Windows 固有 | マニフェスト・パッケージ定義 |
| wwwroot/css | スタイル | app.css, theme.css, sidebar.css 等 |

- **起動・ウィンドウタイトル**: App.xaml.cs で `CreateWindow` をオーバーライドし、`Window.Title = UserMessages.AppTitle` を設定している。MAUI Windows では ContentPage の Title はタイトルバーに反映されないため、ここで設定する。MainPage.xaml の ContentPage にも Title を指定しているが、タイトルバー表示は CreateWindow に依存する。
- **プレビュー**: FilePreviewView は行リスト表示のみ（html モードは廃止）。`Home.Preview.cs` の `SchedulePreviewLoad` が **200ms**（`Home.razor.cs` の `PreviewDebounceMs`）デバウンス後に `LoadPreview` を実行。
- **インデックス構築のキャンセル**: `Home.Index.cs` の `RunIndexUpdateAsync` 等で CancellationTokenSource を保持し、RebuildIndexAsync / UpdateIndexAsync に token を渡す。フッターに「キャンセル」ボタンを表示し、押下で Cancel を呼ぶ。OperationCanceledException 時は進捗テキストを「キャンセルしました」に更新する。進捗表示には IndexProgress.CurrentFile を含め、処理中のファイル名を表示する。
- **スキップ通知**: インデックス完了後、`IndexService.LastSkippedFiles` に 1 件以上あれば件数を SearchSidebar のフッターに警告色で表示する。
- **XML ドキュメント**: 本プロジェクトおよび Core / Infrastructure / Messages の `.csproj` で `GenerateDocumentationFile` を有効にしており、ビルド時に各アセンブリと同じ出力フォルダへ `.xml` が生成される（DocFX 等の入力に利用可能）。

## 4. 主要インターフェース・クラス

### 4.1 インデックス（IIndexService）

**ファイル**: [FullTextSearch.Core/Index/IIndexService.cs](../src/FullTextSearch.Core/Index/IIndexService.cs)

| メソッド | 説明 |
|----------|------|
| InitializeAsync(indexPath, cancellationToken) | インデックスの初期化 |
| IndexDocumentAsync(document, cancellationToken) | 1 件追加/更新 |
| DeleteDocumentAsync(filePath, cancellationToken) | 1 件削除 |
| IndexFolderAsync(folderPath, progress, cancellationToken, progressOffset, progressTotalOverride) | フォルダ全体をインデックス |
| RebuildIndexAsync(folders, progress, options, cancellationToken) | 再構築（全削除＋全件追加） |
| UpdateIndexAsync(folders, progress, options, cancellationToken) | 差分更新 |
| GetStats() | 統計情報取得 |
| OptimizeAsync(cancellationToken) | インデックス最適化 |
| LastSkippedFiles | 直近のインデックス操作でスキップされたファイルパスのリスト（読み取り専用） |

**補助型**:
- **IndexProgress**: ProcessedFiles, TotalFiles, CurrentFile, ProgressPercent, ErrorCount（スキップ件数を含む）
- **IndexRebuildOptions**: TargetExtensions（未指定時は抽出器の対応拡張子を使用）
- **IndexStats**: DocumentCount, LastUpdated, IndexSizeBytes

## 5. データフロー（主要シナリオ）

### 5.1 インデックス作成

```mermaid
sequenceDiagram
  participant UI
  participant IIndex as IIndexService
  participant Lucene
  participant Factory as TextExtractorFactory
  participant Ext as ITextExtractor
  UI->>IIndex: IndexFolderAsync / RebuildIndexAsync
  IIndex->>IIndex: ファイル列挙
  loop 各ファイル
    IIndex->>Factory: GetExtractor(extension)
    Factory-->>IIndex: ITextExtractor
    IIndex->>Ext: ExtractTextAsync(filePath)
    Ext-->>IIndex: テキスト
    IIndex->>Lucene: IndexedDocument を書き込み
  end
```

- 対象フォルダを走査し、拡張子に応じた ITextExtractor でテキスト抽出。
- IndexedDocument に FilePath, FileName, FolderPath, Content, FileSize, LastModified, FileType 等を設定し、Lucene に書き込む。
- **サイズ超過スキップ**: 50MB（`ContentLimits.IndexMaxFileBytesForExtract`）を超えるファイルは本文抽出せずスキップ（null 返却）。スキップされたファイルは `_skippedFiles` に記録される。
- **コンテンツ打ち切り**: 抽出テキストが 500,000 文字（`ContentLimits.ExtractMaxChars`）を超える場合、抽出器（OfficeExtractor / PdfExtractor）が打ち切る。さらに Lucene 格納時にも `ContentLimits.IndexMaxContentChars`（500,000 文字）で打ち切り。
- **並列チャンク処理**: `ProcessChunkAsync` でチャンク内ファイルを並列抽出し、抽出失敗（null）のファイルをスキップログに記録、成功分のみ Lucene に一括追加。Lucene 書き込み失敗時もスキップ件数に加算。
- **スキップログ出力**: 再構築・差分更新の完了後、`WriteSkippedLog` でインデックスフォルダ内に `skipped_files.log` を出力。UI には件数メッセージ（`{N} 件がスキップされました`）のみを表示し、ログファイルのパスは画面上に出さない。当該行のクリックで `skipped_files.log` を既定アプリで開く。

### 5.2 検索

```mermaid
sequenceDiagram
  participant UI
  participant ISearch as ISearchService
  participant Sudachi
  participant Lucene
  UI->>ISearch: SearchAsync(query, options)
  ISearch->>Sudachi: トークナイズ（形態素解析）
  ISearch->>Lucene: 検索＋ハイライト
  Lucene-->>ISearch: SearchResult
  ISearch-->>UI: SearchResult
```

- クエリを Sudachi でトークナイズ（モード C）し、Lucene で検索。
- ハイライト用にマッチ箇所を取得し、SearchResultItem の Highlights に格納。

### 5.3 プレビュー取得

```mermaid
sequenceDiagram
  participant UI
  participant IPreview as IPreviewService
  participant Factory as TextExtractorFactory
  participant Ext as ITextExtractor
  UI->>IPreview: GetPreviewAsync(path, searchQuery)
  IPreview->>Factory: GetExtractor(extension)
  Factory-->>IPreview: ITextExtractor
  IPreview->>Ext: ExtractTextAsync(path)
  Ext-->>IPreview: テキスト
  Note over IPreview: 本文を行ごとに分割し、検索語のみ <mark> で強調
  IPreview-->>UI: PreviewResult (Mode=text, Lines)
```

- ファイルパスと検索クエリ（任意）を IPreviewService.GetPreviewAsync に渡す。
- PreviewService（Blazor）は、抽出器でテキストを取得し、常に Mode = \"text\"・行リスト（Lines）で返す。Office/PDF もテキスト抽出して行リストで表示し、コードであっても構文色分けは行わない。検索語のみを `<mark>` タグで強調表示する。UI では `Home.Preview.cs` の `SchedulePreviewLoad` が **200ms** デバウンス（`Home.razor.cs` の `PreviewDebounceMs`）をかけて `LoadPreview` を呼び、連続クリック時の無駄な抽出を抑えている。

## 6. インデックス構造（Lucene）

**実装**: [FullTextSearch.Infrastructure/Lucene/LuceneIndexService.cs](../src/FullTextSearch.Infrastructure/Lucene/LuceneIndexService.cs)

### 6.1 フィールド名（定数）

| 定数名 | 値 | 用途 |
|--------|-----|------|
| FieldFilePath | "filepath" | ファイルフルパス（一意） |
| FieldFileName | "filename" | ファイル名 |
| FieldFolderPath | "folderpath" | フォルダパス |
| FieldContent | "content" | 抽出テキスト（検索対象。Sudachi でトークナイズ） |
| FieldFileSize | "filesize" | ファイルサイズ |
| FieldLastModified | "lastmodified" | 最終更新日時 |
| FieldFileType | "filetype" | ファイル種類の表示名（`IndexMessages.GetFileTypeDisplayName` による日本語ラベル。例: Word文書、PDFファイル） |
| FieldIndexedAt | "indexedat" | インデックス登録日時 |

### 6.2 アナライザ

- **SudachiAnalyzer**（Sudachi モード C）を使用。
- アナライザを変更した場合、既存インデックスは互換性がなくなる。再構築が必要。

### 6.3 タイムアウト保護（SudachiTokenizer）

SudachiPy サブプロセスとの通信がハングしてインデックス構築が無応答になる問題を防止するため、`System.Threading.Timer`（ウォッチドッグタイマー）を各呼び出し方式に設定している。

| 呼び出し方式 | タイムアウト | 定数名 |
|---|---|---|
| InvokeSudachiStream | 60 秒 | StreamTimeoutMs |
| InvokeSudachiBatch | 120 秒 | BatchTimeoutMs |
| InvokeSudachiOneshot | 60 秒 | OneshotTimeoutMs |

- タイムアウト経過時はウォッチドッグが Python プロセスを `Kill()` し、呼び出し側は `null` を返す（スキップ扱い）。
- `Process.BeginErrorReadLine()` で stderr を非同期ドレインし、パイプデッドロックを防止する。

## 8. 拡張子・プレビュー種別

### 8.1 抽出器別対応拡張子

| 抽出器 | 拡張子 | PreviewCategory |
|--------|--------|-----------------|
| OfficeExtractor | .docx, .xlsx, .pptx | Text |
| PdfExtractor | .pdf | Pdf |
| TextFileExtractor | .txt, .csv, .log, .md, .cs, .js, .ts, .jsx, .tsx, .py, .java, .cpp, .c, .h, .hpp, .pas, .dpr, .dpk, .html, .htm, .css, .scss, .sass, .less, .xml, .json, .yaml, .yml, .sql, .sh, .bat, .ps1, .ini, .cfg, .conf, .config, .gitignore, .env | Text |

※ 一覧の詳細は各 Extractor の SupportedExtensionSet を参照（[静的定義一覧](静的定義一覧.md) も参照）。

### 8.2 プレビュー種別と抽出器の対応

- **Text**: テキスト・ソースコードとして表示。TextFileExtractor および OfficeExtractor（.docx/.xlsx/.pptx）はいずれも PreviewCategory=Text で、抽出テキストの行表示のみ。
- **Pdf**: PDF。PdfExtractor が対応。プレビューもテキスト抽出の行表示（表形式・ネイティブプレビューは使用しない）。

※ プレビュー種別は抽出器の PreviewCategory から導出しており、拡張子の二重管理はない。[静的定義一覧](静的定義一覧.md) 参照。
