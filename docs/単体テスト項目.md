# 単体テスト項目（現状版）

本書は、**手動の画面操作チェック**（`docs/テストチェックリスト.md`）とは役割を分け、**自動化する単体テスト**で何を担保すべきかを整理したものです。  
実装状況は `tests/FullTextSearch.Tests` の xUnit テストを基準に記載しています。

---

## 1. 用語の整理

| 区分 | 内容 | 本書の位置づけ |
| --- | --- | --- |
| 単体テスト | クラス・メソッド単位。外部 I/O（実ディスク・Lucene 実体・WebView）を置き換えまたは最小化する。 | **本書の主対象** |
| 統合テスト | Lucene 一時ディレクトリ＋小さな本文ファイル、Sudachi 起動など。 | 本書では「補足・別票」扱い |
| UI / E2E | Blazor コンポーネント操作、MAUI ウィンドウ。 | `テストチェックリスト.md` 側 |

### 3.1 仕様（要件定義）との対応（トレーサの目安）

単体テストは**画面・E2E の受入**を置き換えるものではない（その役割は `docs/テストチェックリスト.md`）。下表は、**コード上の定数・文言・純粋ロジック**で要件のうち何を間接的に固定しているかの整理である。

| 要件 | 本テストで触れている主な箇所 |
| --- | --- |
| REQ-1.2（拡張子） | `AppSettingsService` の拡張子正規化・往復。未指定時挙動は**設定/UI の仕様**（手動＋`PreviewHelper`） |
| REQ-1.3（インデックス保存先） | デフォルトパス形: `DefaultPathsTests`。保存先の妥当性検証は UI/手動 |
| REQ-2.3 / REQ-2.6（進捗・スキップログ文言） | `UserMessages` / `IndexMessages` フォーマット。実際のログ出力パスはインデックス配下（統合未） |
| REQ-2.5（1MB 超スキップ） | 閾値＝`IndexMaxFileBytesForExtract`（**1MB**）、**超過判定**＝`ExceedsIndexTextExtractionFileSizeLimit`（`ContentLimitsTests`） |
| REQ-3.3（ツリー等） | `TreeBuilder` の階層化・件数。検索**結果の中身**は Lucene 未 |
| REQ-3.4 / ハイライト文言 | `UserMessages` のナビ用フォーマット。実ハイライトは手動/Blazor 未 |
| 非機能（上限・UTF-8 用語） | `LuceneMaxTermUtf8Bytes` 等 |

**仕様と「完全一致」とは言い切れない例:** 検索件数上限なし（内部実用上限のみ）、Sudachi モード C、200ms デバウンス、Ctrl+ズーム、差分/全構築のトランザクション挙動などは、**単体テストの外**（手動または今後の統合テスト）で確認する想定。

## 6. メンテナンス指針

- **仕様変更**（正規化ルール、文言、進捗形式）を入れた PR では、対応する **UT-*** または **実装-*** テストを同時に更新する。
- 新規に純粋関数を `Core` に追加したら、**UT-CORE-*** に 1 行でも項目を足す（または即テスト実装）と追跡しやすい。
- 本書の項目 ID と `テストチェックリスト.md` の手動 No. は**対応付け不要**（目的が異なるため）。必要なら受入試験票で **トレーサブルマトリクス**を別紙化する。
